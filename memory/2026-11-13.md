## 途中定位并修掉的三个真 bug

1. **采样公式半数 module 偏移**（E2E 全红根因）：`(i - 3.5)` 应为 `(i - 3.0)`——module 索引 i 的中心坐标为 `i+0.5`，相对 finder 中心 3.5 的位移是 `i-3`。修正后 42 个错位 module → 0。
2. **`unit = r3/3.0` 使 r3 比例检查恒真**：unit 用 r3 自身推导，导致 1:1:5:1:1 中心过宽的图案也能通过比例闸。改用 `total/7`（全 7 module 宽度）估计，比例闸恢复效力（白盒反例测试这才真正拒绝）。
3. **测试里 `FixedArray::make(3, FixedArray::make(3,0))` 内层数组被三行共享**：赋初值时互相覆盖，导致旋转测试断言值全错。修法：逐行 `FixedArray::make(3, 0)` 重新分配（项目既有惯例）。

## 已知边界（如实登记，未收口）

- **不含透视校正**：仿射模型仅覆盖缩放/平移/旋转（90° 倍数）与轻微形变；强透视（斜拍）需后补 homography
- **亮度极端不均**未处理：全局 Otsu 在局部阴影/反光下会失效，需自适应局部阈值
- **PNG 文件直读未做**：像素需调用方（浏览器 canvas / Python PIL）提取后传入；项目 PNG 用 stored blocks，自写 inflate 读回是后续可选项

## T0.5 续：透视校正（homography + alignment pattern）（P2）

**交付**（`src/qr/image_decode.mbt` 扩展）：
- `rle_line`：抽出游程编码供两种扫描共用（重构零回归）
- `scan_alignment_hits`：1:1:1:1:1 剖面扫描（alignment pattern 特征，finder 的 1:1:3:1:1 不会误命中）
- `solve_linear_8` + `solve_homography`：8×8 高斯消元（部分主元）求单应矩阵
- `sample_matrix_homography`：单应反投影采样（复用 `sample_vote`）
- `find_alignment_point`：以仿射预测位置为中心、局部窗口搜索 alignment 候选并行列交叉配对
- `try_decode_perspective`：三点仿射失败后，用右下 alignment pattern 作第四点求单应重采样（4 旋转重试）
- `estimate_size` / `affine_map` / `sample_vote`：抽出复用

**测试**（`image_decode_wbtest.mbt` 追加 4 格）：
- `wb_warp` 透视变形 helper（四点单应反向采样，模拟斜拍）
- `wb alignment scan ignores finder rows`（机制格：finder 剖面不被 alignment 扫描误命中）
- `wb alignment scan detects 1:1:1:1:1`（正例）
- `wb unwarped source decodes`（对照：原图走仿射）
- `wb perspective warp decodes through homography`（梯形变形端到端解码）
